# Incident Disclosure Navigator — GitHub Pages版

サイバーインシデント発覚後の報告判断、社内外調整、文案作成、対応計画を支援するブラウザーアプリです。

このフォルダーは、そのままGitHub Pagesへ配置できる静的ファイル一式です。Node.js、データベース、APIキーは必要ありません。

## ファイル構成

- `index.html`：画面の構造
- `styles.css`：画面デザイン
- `app.js`：判定、文案、履歴、Excel・JSON出力
- `.nojekyll`：GitHub Pagesでそのまま配信するための設定

## GitHub Pagesで公開する手順

1. GitHubで新しいPublicリポジトリを作成する
2. このフォルダー内の4ファイルをリポジトリ直下へ配置する
3. GitHubのリポジトリで `Settings` → `Pages` を開く
4. `Build and deployment` のSourceを `Deploy from a branch` にする
5. Branchを `main`、フォルダーを `/(root)` にして保存する
6. 公開処理が終わったら、表示されたURLを開く

通常のURLは次の形式です。

```text
https://GitHubユーザー名.github.io/リポジトリ名/
```

## 公開後の確認項目

- 「空白から新規作成」を選べる
- 事案情報を入力して「判定を更新」できる
- 文案を生成・コピー・PDF印刷できる
- Excelガントチャートを出力できる
- JSONを出力できる
- 案件を保存し、履歴から再読込できる
- PCとスマートフォンの両方で表示できる

## この版の動作

- 初動判定はJavaScriptのルールで行います。
- 文案はブラウザー内のローカルテンプレートで生成します。
- 入力情報を外部のLLM APIへ送信しません。
- 案件履歴は利用者のブラウザー内に保存されます。
- 利用者間で案件情報は共有されません。

## LLM連携について

GitHub Pagesは静的サイト用のため、サーバー側のLLM呼び出しは含めていません。将来LLMを接続する場合は、APIキーをブラウザーへ埋め込まず、サーバーレス関数などのバックエンド側で管理してください。

## 注意事項

- 本システムは法的助言を行うものではありません。
- 判定結果と文案は、法務部門や個人情報保護責任者などが確認してください。
- 公開デモには、実在企業の機密情報や実際のインシデント情報を入力しないでください。
